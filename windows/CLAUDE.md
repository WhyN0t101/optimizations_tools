# FocusedTweaks: guide for Claude Code

A Windows tweak script derived from ZOICWARE (MIT). Read `docs/SUMMARY.md` first (what it is, safety model, decisions,
test status); `docs/CHANGELOG.md` holds the history, newest first. Every change gets a line under its Unreleased
heading.

## Layout
- `src/NN-name.ps1` is the SOURCE OF TRUTH: one file per area (00 header and parameters, 01 options, 02 data,
  03 infrastructure, 04 registry primitives, ... 17 health check, 18 orchestration, 19 entry point). Joined in name
  order they form the template; a function's file is the area it belongs to.
- `FocusedTweaks.ps1` is GENERATED by `python tools/build.py --out FocusedTweaks.ps1` (run in `windows/`).
  Never edit it by hand. Change the file in `src/`, build, then run the tests. The build inserts upstream data (registry
  file, telemetry values, domain lists, mouse curves, Start layout) so `src/02-data.ps1` holds only placeholders for those.
  It also writes `docs/OPTIONS.md` and `docs/REGISTRY.md`.
  The build needs Python 3. It reads the three ZOICWARE files kept in `upstream/zoicware/` (commit 2363922; the
  ZOICWARE repository left GitHub on 8 Nov 2026) and checks them against the SHA256 values in `ZOICWARE_FILES`.
  Never edit those files.
- CI (`.github/workflows/windows-build.yml`) builds on every push, fails if the committed `FocusedTweaks.ps1` or
  `docs/OPTIONS.md` differ from the build, and runs `Test-Parse` under 5.1 and 7. Pushing a `v*` tag runs
  `windows-release.yml`, which refuses a commit without a successful smoke test run, stamps the tag into the header
(`build.py --version`; there is no version commit, `src/00-header.ps1` holds `__FT_VERSION__`), and publishes the built script, its SHA256 and NOTICE.md as a GitHub release, with a
  build provenance attestation. Actions are pinned by commit SHA with the tag in a comment (`Test-Parse` checks it).
- `windows-smoke.yml` runs the script for real on throwaway runners, Windows Server 2025 (x64) and Windows 11
  (`windows-11-arm`, ARM64), through `tools/Test-Smoke.ps1` (dry runs, apply, health check, reapply, revert), on every
  push and every Monday, and uploads `smoke-results-<runner>`. Test-Smoke refuses to run outside GitHub Actions.
  Server lacks Store apps, Quick Assist and restore points; the ARM runner has them but no NVIDIA and emulates x64
  installers. The VM test remains the x64 Windows 11 check with a real reboot.
- `tests/Test-Parse.ps1` is a static check that needs no admin rights and changes nothing. Run it with both `pwsh` and
  `powershell.exe`. It also builds a junction in a scratch folder to prove the cleanup never follows links, and tests
  the journal rules in a scratch key under `HKCU\Software\FocusedTweaksTest-<id>`; both are removed again.
- `profiles/example.json` shows the format for `-ProfilePath`.
- Windows only. The script elevates itself.

## Hard rules
1. Never run `FocusedTweaks.ps1` on this machine, not even with `-DryRun`. Here: build and `tests/Test-Parse.ps1` only.
   Dry runs and real runs happen only in the test VM, after a snapshot.
2. A new option also needs a place in `OPTION_GROUPS` in `tools/build.py` (the build fails otherwise), and an entry in
   `NOT_REVERTED` if `-Revert` cannot undo it. The build writes `docs/OPTIONS.md` from it; never edit that file by hand.
3. Every change that alters the system must (a) go through `Test-DryRun`, (b) record the original state so `-Revert` works,
   (c) have a line in the health check, and (d) sit behind an option in `$OptionInfo`. Record state only through the
   journal helpers (`Set-RegValue`, `Remove-RegValue`, `Remove-RegKey`, `Set-StateValue`, `Add-StateRecord`, the task
   helpers), before the change; never assign `$script:State` directly. `Test-Parse` checks this.
4. Stay compatible with Windows PowerShell 5.1: no ternary operator, no `??`, no `&&`. The script uses `Set-StrictMode -Version Latest`.
5. A hashtable entry name can shadow a property: never name a `$script:State` entry `Keys`, `Values` or `Count`.
6. Output encoding is UTF-8 with BOM, CRLF line endings, ASCII only. `build.py` writes this. `.gitattributes` keeps it.
7. Native commands need `$LASTEXITCODE` checked. .NET method errors arrive wrapped, so use `Test-AccessDenied` rather than typed catch blocks.
8. JSON state: PowerShell 7 turns ISO date strings into dates when reading JSON. Registry strings are stored with an `s:` prefix for that reason.
9. The run in progress is `$Ctx` (made once in `src/00-header.ps1`): dry run, reapply, after-apply flags, failure and
   warning counters, the current step and its journal option. Read and change it there; never add a `$script:` flag
   for run state, and never name a local variable `$ctx` (names are case-insensitive). `Test-Parse` checks this.

## Workflow for a change
Edit the file in `src/`, then run `tools/Check.ps1` (build plus `Test-Parse` under 5.1 and 7, stops at the first
failure; the pre-commit hook in `.githooks/` runs it with `-Staged`, on after `git config core.hooksPath .githooks`), then let the user run `tools/Test-InVm.ps1` (see
`docs/VM-TESTING.md`). It drives the VM with vmrun through dry run, real run, restart, health check and `-Revert`, and
copies logs and JSON results to `test-results/<time>/`. Read `summary.txt` there first.

## Other projects (reference only)
`python tools/coverage.py` compares the built script with winutil, Win11Debloat, Sophia Script and privacy.sexy at
the commits pinned in `tools/references.json` (`--update` moves the pins) and writes `docs/COVERAGE.md`. It downloads
into `.cache/` (ignored) and needs the network, so CI does not run it. Its rows are leads: check each in `src/` and
add it the usual way (option, journal, health check). Never copy from privacy.sexy (AGPL-3.0); credit an MIT project
in NOTICE.md if its data is taken over, as with ZOICWARE.

## What Windows ships (inventory)
`tools\Get-Inventory.ps1` lists a Windows' services, tasks, Store apps, startup entries and optional features and marks
each handled (read from the built script's lists), kept, reviewed (`tools\inventory-known.json`, with a reason) or
unknown; with `-Previous` it also lists what is new since. The smoke run does it on the fresh Windows 11 runner before
any stage (summary section "Inventory of the fresh image"; the last main run is kept in the Actions cache), and
`Test-InVm.ps1 -Stages Inventory` in the VM. An unknown item ends up in an option or in inventory-known.json.

## When upstream changes
Only if ZOICWARE becomes available again (or a fork is chosen): build once with `--zoicware <new checkout>
--allow-other-commit` (the build asserts the expected list sizes and fails loudly), copy its three files into
`upstream/zoicware/src`, update `ZOICWARE_COMMIT` and `ZOICWARE_FILES` in build.py and the folder's README, then
run the tests and a VM dry run.
